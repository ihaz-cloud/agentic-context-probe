### 2026-04-27 — Bootstrap prompt under-specifies dependency-graph wiring

**Discovered while:** Running `/scribe-init` (vibe-md-templates `bootstrap.sh`) to set up this Scale-tier project. After 30 beads were created, an audit pass revealed the dep graph was under-wired in three ways: (a) within-phase child-to-child links missing on `0to.9`/`0to.10`, (b) Phase 3 children gated only by the coarse `0to` epic when fine-grained `0to.1`+`0to.3`+`0to.6` deps would enable earlier parallel start, (c) a source-document contradiction between `DESIGN.prd.md §4.1` and `lessons_learned/cli-vs-direct-api.md` was not surfaced as a decision bead in the original sweep.

**Gap:** `vibe-md-templates/scripts/bootstrap.sh` line 659 has a single sentence about deps:
> "5. Set dependencies where one bead blocks another: bd dep add <later-id> <earlier-id> -t blocks"

It does not operationalize the readiness rule from `rules/work-item-templates.md` ("Prose dependencies that aren't formalized are a defect"), does not distinguish epic-to-epic vs child-to-child granularity, and does not direct the agent to verify with `bd ready` / `bd dep tree` / `bd lint` before declaring done.

**Where it should live:** `vibe-md-templates/scripts/bootstrap.sh` — the BEADS CREATION prompt section.

**Suggested fix:** Patch drafted at `.claude/bootstrap-prompt-deps.patch` and verified to apply cleanly. Adds: (a) granularity guidance, (b) prose-must-match-graph audit rule, (c) `bd ready` / `bd dep tree` / `bd lint` verification step, (d) multi-file PRD handling that surfaces cross-source contradictions as decision beads, (e) `--type decision` callout. Hand to repo owner via the patch file.

**Status:** [OPEN] — patch drafted, not yet submitted upstream.

### 2026-04-27 — bd 0.57.0 .beads/.gitignore missing dolt runtime patterns

**Discovered while:** Running `git status` after `bd init` populated `.beads/`. Three runtime artifacts the dolt daemon writes are not in the bundled `.beads/.gitignore` and were being tracked as modified-on-every-tick: `dolt-monitor.pid`, `dolt-server.activity`, `dolt-server.port`.

**Gap:** `.beads/.gitignore` is generated by `bd init` (upstream beads, not this repo). Lines 30–32 list `dolt-server.pid`, `dolt-server.log`, `dolt-server.lock` but do not generalize to `dolt-server.*` or include `dolt-monitor.*`. The fix is upstream in `https://github.com/steveyegge/beads`, not in `vibe-md-templates`.

**Where it should live:** Upstream beads template for `.beads/.gitignore`.

**Suggested fix (upstream):**
```diff
- dolt-server.pid
- dolt-server.log
- dolt-server.lock
+ dolt-server.*
+ dolt-monitor.*
```

**Status:** [OPEN] — diagnosis recorded; user deferred drafting the upstream patch.

### 2026-04-27 — Bootstrap prompt does not direct agent to read sibling PRD docs

**Discovered while:** Populating `.claude/` templates from `prd/DESIGN.prd.md`. The `prd/` directory also contained `research.md`, `lexicon.prd.md`, and `lessons_learned/*.md` — together with material that *contradicts* the named source. The bootstrap prompt only names a single source and says "Extract ALL information from it." Without explicit guidance, the agent (me) read only the named source on the first pass and missed the contradiction; only the user's follow-up audit caught it.

**Gap:** Same file as Entry 1 (`bootstrap.sh`), different prompt section — the source-document handling block, not the beads creation block.

**Where it should live:** `vibe-md-templates/scripts/bootstrap.sh` — the `if [ -n "$SOURCE_DOC_ABS" ]` branch of the prompt.

**Suggested fix:** Covered by the same patch as Entry 1. Adds: "If the source document lives in a directory with sibling docs (e.g. research.md, lessons_learned/, lexicon.prd.md), READ THOSE TOO. ... When sibling docs DISAGREE with the named source, do not silently pick one — surface the contradiction explicitly and, if beads are enabled, create a decision-type bead to resolve it."

**Status:** [OPEN] — bundled into the same patch as Entry 1.
